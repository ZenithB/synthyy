# Releasing Synthtagram Desktop

End-to-end runbook for shipping the Tauri 2 desktop app. The web app is
untouched by any of this — it keeps deploying to Vercel on every push to `main`.

Everything is driven by **environment variables / CI secrets**. No credential,
certificate or key is ever committed. `git grep -i "apple_password"` should only
ever hit docs, the script and the workflow.

## 0. What is already wired

| Piece | Where |
|---|---|
| Bundle config (app + dmg on macOS, msi + nsis on Windows), icons | `src-tauri/tauri.conf.json`, `src-tauri/icons/` (generated by `npx tauri icon src-tauri/icons/icon.png`) |
| Hardened-runtime entitlements (`audio-input` only; see comments for why no JIT keys) | `src-tauri/Entitlements.plist` |
| `NSMicrophoneUsageDescription` + app category | `src-tauri/Info.plist` (merged by the bundler via `bundle.macOS.infoPlist`) |
| `minimumSystemVersion` 13.0, `hardenedRuntime: true`, `signingIdentity: null` | `tauri.conf.json` — `null` means "use `APPLE_SIGNING_IDENTITY` from the env" |
| Local release script | `scripts/release-macos.sh` (`--unsigned` for a local unsigned DMG) |
| CI on `v*` tags | `.github/workflows/desktop-release.yml` |

## 1. One-time: Apple Developer setup (owner does this, by hand)

1. Enrol in the Apple Developer Program (paid, yearly) and note the **Team ID**
   (developer.apple.com/account → Membership details, 10 characters).
2. Create a **Developer ID Application** certificate
   (developer.apple.com/account/resources/certificates → "+" → Developer ID
   Application). Use Keychain Access → Certificate Assistant → Request a
   Certificate From a Certificate Authority to make the CSR on your Mac.
   Download the `.cer`, double-click to install into the *login* keychain.
   Also install Apple's current "Developer ID" intermediate if Keychain shows
   the cert as untrusted.
3. Confirm it is usable:
   ```bash
   security find-identity -v -p codesigning
   # 1) ABCDEF… "Developer ID Application: Your Name (TEAMID)"
   ```
   The quoted string is your `APPLE_SIGNING_IDENTITY`.
4. Notarization credentials — pick one:
   - **Apple ID + app-specific password** (simplest): appleid.apple.com →
     Sign-In and Security → App-Specific Passwords → generate one named
     `synthtagram-notary`. This is `APPLE_PASSWORD`; `APPLE_ID` is the account
     email; `APPLE_TEAM_ID` from step 1.
   - **App Store Connect API key** (better for CI): appstoreconnect.apple.com →
     Users and Access → Integrations → Team Keys → generate with *Developer*
     role. Gives `APPLE_API_KEY` (key ID), `APPLE_API_ISSUER` (issuer UUID) and
     the `AuthKey_<KEYID>.p8` file (`APPLE_API_KEY_PATH`). The .p8 can only be
     downloaded once.
5. For CI: export the certificate **with private key** from Keychain Access as
   a `.p12` with a strong password, then
   `base64 -i DeveloperID.p12 | pbcopy` → this is the `APPLE_CERTIFICATE`
   secret, the password is `APPLE_CERTIFICATE_PASSWORD`. Delete the `.p12`
   afterwards.

## 2. Local signed release

```bash
# put these in a git-ignored file, e.g. .env.release.local (matches *.local in .gitignore)
export APPLE_SIGNING_IDENTITY="Developer ID Application: Your Name (TEAMID)"
export APPLE_ID="you@example.com"
export APPLE_PASSWORD="xxxx-xxxx-xxxx-xxxx"   # app-specific password
export APPLE_TEAM_ID="TEAMID"
# — or — APPLE_API_KEY / APPLE_API_ISSUER / APPLE_API_KEY_PATH

source .env.release.local
scripts/release-macos.sh
```

The script:

1. Lists exactly which variables are missing (and where to get each) and
   exits if any are; checks the identity actually exists in a keychain.
2. Installs the `x86_64-apple-darwin` Rust target if needed.
3. Runs `npm run tauri build --target universal-apple-darwin --bundles app,dmg`.
   Tauri signs the `.app` (hardened runtime + `Entitlements.plist`), builds the
   DMG, signs it, submits it to Apple's notary service, **waits** for the
   verdict (usually 1–10 min, occasionally longer), and staples the ticket to
   both the `.app` and the `.dmg`.
4. Verifies: `codesign --verify --deep --strict`, `spctl -a -vv -t exec`
   (must say `accepted … source=Notarized Developer ID`),
   `xcrun stapler validate` on app and dmg, and prints the paths.

Output: `target/universal-apple-darwin/release/bundle/{macos/Synthyy.app,dmg/Synthtagram_<ver>_universal.dmg}`.

Unsigned local build (no Apple account needed):

```bash
scripts/release-macos.sh --unsigned
```

Gatekeeper will refuse to open that DMG's app on another machine
(right-click → Open, or `xattr -dr com.apple.quarantine Synthyy.app`).

### If notarization fails

Tauri prints the submission ID. Get the log with

```bash
xcrun notarytool log <submission-id> --apple-id "$APPLE_ID" --password "$APPLE_PASSWORD" --team-id "$APPLE_TEAM_ID"
```

Typical causes: a nested binary/dylib not signed with hardened runtime
(Tauri signs everything under `Contents/` — check third-party frameworks you
added via `bundle.macOS.frameworks`), missing secure timestamp (network), or an
entitlement that needs justification. Do **not** add
`com.apple.security.cs.allow-jit` / `allow-unsigned-executable-memory` to make
a failure go away; WKWebView's JIT lives in Apple's WebContent XPC process and
does not need them (see comments in `Entitlements.plist`).

## 3. CI release (GitHub Actions)

Workflow: `.github/workflows/desktop-release.yml`, triggered by pushing a tag
`v*` (or manually via *Run workflow*). It creates a **draft** GitHub Release
with the artifacts attached; you publish it by hand after a smoke test.

Add these repository secrets (Settings → Secrets and variables → Actions):

| Secret | Value |
|---|---|
| `APPLE_CERTIFICATE` | base64 of the Developer ID Application `.p12` (step 1.5) |
| `APPLE_CERTIFICATE_PASSWORD` | password used when exporting the `.p12` |
| `APPLE_SIGNING_IDENTITY` | `Developer ID Application: Your Name (TEAMID)` |
| `APPLE_ID` | Apple ID email |
| `APPLE_PASSWORD` | app-specific password |
| `APPLE_TEAM_ID` | Team ID |
| `WINDOWS_CERTIFICATE` *(optional)* | base64 of an Authenticode `.pfx` |
| `WINDOWS_CERTIFICATE_PASSWORD` *(optional)* | its password |

With no secrets set, both jobs still run and attach **unsigned** installers.
The macOS job imports the `.p12` into a throwaway keychain, runs
`tauri-apps/tauri-action@v0` (which builds, signs, notarizes and staples using
the same env vars as the local script), then re-verifies with
`spctl` / `stapler validate`.

Cut a release:

```bash
# bump "version" in src-tauri/tauri.conf.json AND [workspace.package].version in Cargo.toml
git commit -am "release: v0.2.0"
git tag v0.2.0
git push origin main --tags
```

Then watch Actions → *desktop-release*, download the DMG from the draft
release, open it on a clean Mac (no developer tools) and confirm it launches
without a Gatekeeper warning, then click *Publish release*.

## 4. Windows notes

- The Windows job produces `Synthtagram_<ver>_x64_en-US.msi` (WiX) and
  `Synthtagram_<ver>_x64-setup.exe` (NSIS). WebView2 is installed by the
  bootstrapper if missing (`webviewInstallMode: downloadBootstrapper`).
- Signing: `bundle.windows.certificateThumbprint` is committed as `null`. When
  `WINDOWS_CERTIFICATE` is present the job imports the `.pfx` into the
  runner's `CurrentUser\My` store and passes the resulting thumbprint through
  `tauri build --config '{"bundle":{"windows":{"certificateThumbprint":"…"}}}'`,
  so the committed config never changes. Timestamping uses
  `http://timestamp.digicert.com` (sha256).
- OV certificates still trigger SmartScreen "unknown publisher" until the
  cert has reputation; an EV cert (hardware token / cloud HSM) avoids that. For
  an HSM-backed cert use `bundle.windows.signCommand` (e.g. AzureSignTool)
  instead of a thumbprint.
- Windows installers are built with `--features asio` (ASIO driver support;
  `asio-sys` downloads the Steinberg SDK at build time, libclang is on the
  runner). Check Steinberg's licence terms before distributing beyond
  personal use.
- Hardware verification (WASAPI + ASIO) is the checklist in `docs/WINDOWS.md`.

## 5. Auto-update (deliberately not enabled yet)

`tauri-plugin-updater` requires every release to be signed with a
**minisign keypair** whose public key is baked into `tauri.conf.json` and whose
private key must be kept out of the repo. Since there is nowhere safe to keep
that key right now, the plugin is not added. To enable it later:

1. Generate the keypair **outside the repo**:
   `npx tauri signer generate -w ~/.tauri/synthtagram.key` (set a password).
   Back up `~/.tauri/synthtagram.key` in a password manager — losing it means
   existing installs can never update again.
2. Add the plugin: `cargo add tauri-plugin-updater --package synthyy`,
   `npm i @tauri-apps/plugin-updater`, register it in `src-tauri/src/lib.rs`
   (`.plugin(tauri_plugin_updater::Builder::new().build())`), and add
   `"updater:default"` to `src-tauri/capabilities/default.json`.
3. In `tauri.conf.json` add
   ```json
   "plugins": { "updater": {
     "pubkey": "<contents of ~/.tauri/synthtagram.key.pub>",
     "endpoints": ["https://github.com/<owner>/<repo>/releases/latest/download/latest.json"]
   }},
   "bundle": { "createUpdaterArtifacts": true }
   ```
4. Add CI secrets `TAURI_SIGNING_PRIVATE_KEY` (file contents) and
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, pass them as `env` to the
   `tauri-action` steps, and set `includeUpdaterJson: true` on the action so it
   uploads `latest.json`.
5. Call `check()` / `downloadAndInstall()` from the UI on launch.

Updater artifacts must be notarized too — the existing signing env handles
that automatically.
